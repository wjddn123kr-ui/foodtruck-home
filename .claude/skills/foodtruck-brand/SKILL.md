# 푸드트럭하우스 홈페이지 브랜드 & 모션 가이드

푸드트럭하우스 공식 홈페이지(`foodtruck-home` repo, **단일파일 `index.html`**)를 작업할 때 따르는 디자인·모션·콘텐츠 규칙이다. 목표는 한 가지: **청춘여행 레퍼런스의 산뜻하고 젊은 무드를 유지하면서, AI가 찍어낸 듯한 뻔한 비주얼을 피하는 것.**

---

## 0. 가장 먼저 — 진실의 원천(Source of Truth)

색상·폰트·간격 토큰은 이 문서가 아니라 **현재 `index.html`의 `:root` 변수가 진실**이다.
작업 시작 시 항상:

1. `index.html`의 `:root { ... }` 블록을 먼저 읽는다.
2. 거기 정의된 CSS 변수(`--sky-*`, `--ink`, 폰트 등)를 그대로 사용한다.
3. 새 색을 하드코딩하지 말고, 기존 변수를 쓰거나 `:root`에 변수를 추가한 뒤 참조한다.

아래 4·5번의 토큰 값은 **`:root`가 비어있거나 새로 만들 때 쓰는 폴백 기본값**이다. 실제 파일 값과 다르면 **실제 파일 값이 이긴다.**

---

## 1. 브랜드 아이덴티티

- **슬로건(고정):** "젊음이 만든 열정, 깨끗한 푸드트럭의 기준."
- **무드:** 청춘여행 레퍼런스 기반 — 밝고 산뜻한 하늘색 그라데이션, 여백이 넉넉하고, 무겁지 않고 젊다.
- **톤 키워드:** 젊음 · 열정 · 깨끗함 · 신뢰 · 실행력
- **피해야 할 것:** 무겁고 어두운 기업형 네이비 일색, 촌스러운 형광 포인트, 과한 그림자.

> 참고: 이전 방향(딥 네이비 + 일렉트릭 블루 #2D5BFF)에서 **소프트 스카이블루 그라데이션으로 전환 완료**. 옛 네이비 무드로 되돌아가지 말 것.

---

## 2. 레이아웃 원칙

- **모든 페이지는 단일파일 `index.html`** 안에서 작업한다. CSS·JS를 별도 파일로 분리하지 않는다(`<style>`, `<script>` 인라인 유지).
- 섹션은 풀폭(full-bleed) 기반, 콘텐츠는 가운데 정렬 컨테이너(max-width 약 1200px).
- 섹션 사이 여백은 넉넉하게. 답답하지 않게.
- 모바일 우선. 모든 모션·격자는 모바일에서 깨지지 않아야 한다.

---

## 3. 시그니처 — 호차 배차 격자

**호차 배차 격자(라이브 배차 보드)는 푸드트럭하우스의 시그니처 비주얼이다. 절대 빼거나 평범한 표/리스트로 대체하지 말 것.**

- 호차 × 요일(또는 시간) 격자 형태.
- 셀이 실시간으로 채워지는/움직이는 라이브 애니메이션을 유지한다(아래 6.5 참조).
- "지금 우리 트럭들이 전국에서 동시에 돌고 있다"는 인상을 주는 것이 핵심.

---

## 4. 컬러 시스템 (폴백 기본값)

`:root`에 없을 때만 쓰는 기본 토큰. 소프트 스카이블루 그라데이션 무드.

```css
:root {
  /* 하늘색 그라데이션 코어 */
  --sky-50:  #f0f7ff;  /* 가장 옅은 배경 */
  --sky-100: #dcebff;  /* 섹션 배경 톤 */
  --sky-200: #bfe0ff;
  --sky-300: #93cbff;  /* 그라데이션 시작 */
  --sky-400: #5db4ff;  /* 메인 스카이블루 (키컬러) */
  --sky-500: #2f9bff;  /* 강조/버튼 */
  --sky-600: #1d7fe6;  /* 호버/딥 포인트 */

  /* 텍스트 */
  --ink:      #0f2540;  /* 본문(네이비 잉크, 배경 아님) */
  --ink-soft: #4a6party; /* 보조 텍스트 — 실제 파일값 우선 */
  --white:    #ffffff;

  /* 시그니처 그라데이션 */
  --grad-hero: linear-gradient(160deg, var(--sky-50) 0%, var(--sky-200) 55%, var(--sky-300) 100%);
  --grad-cta:  linear-gradient(135deg, var(--sky-400), var(--sky-600));
}
```

> 위 값에 `#4a6party` 같은 명백한 자리표시가 있으면 무시하고 실제 `index.html`의 보조 텍스트 색을 따른다. **컬러는 늘 실제 `:root`가 우선.**

**사용 규칙**
- 큰 배경면: `--sky-50` ~ `--sky-200` + `--grad-hero`.
- 버튼·핵심 CTA: `--grad-cta`, 텍스트는 흰색.
- 본문 텍스트는 하늘색이 아니라 `--ink`(네이비 잉크)로. 하늘색을 본문에 쓰면 가독성이 무너진다.
- 포인트는 절제. 한 화면에 강조색은 1~2개까지.

---

## 5. 타이포그래피

- 한글 헤드라인은 **굵고 임팩트 있게**(700~800), 자간 살짝 좁게.
- 본문은 가독성 우선(400~500), 줄간격 넉넉히(1.6~1.7).
- 폰트는 `:root`/`<head>`에 정의된 것을 따른다(Pretendard 계열 권장). 새로 추가하지 말고 기존 것을 쓴다.
- 숫자(스탯)는 헤드라인급으로 크게 — 카운트업의 주인공이다(6.2 참조).

---

## 6. 모션 컨벤션 — 이미 구현된 6개 섹션

아래 6개 섹션의 모션은 **이미 구현 완료**되어 있다. 새 작업은 이 스타일과 **결을 맞춰서** 추가하고, 기존 모션을 함부로 단순화하거나 제거하지 않는다.

공통 원칙:
- 이징은 부드럽게(`cubic-bezier(0.16, 1, 0.3, 1)` 류), 튀지 않게.
- 스크롤 진입 시 `IntersectionObserver`로 한 번만 발동(반복 깜빡임 금지).
- 모바일에서 프레임 드랍 나는 무거운 효과는 지양.
- `prefers-reduced-motion: reduce`를 존중해 모션 최소화 분기를 둔다.

### 6.1 히어로 영상
- 상단 풀스크린 배경 영상 + 소프트 스카이블루 그라데이션 오버레이.
- 그 위에 슬로건/핵심 카피가 또렷이 읽혀야 함(오버레이로 대비 확보).
- 영상은 자동재생·무음·루프, 모바일 폴백 이미지 준비.

### 6.2 카운트업 스탯
- 핵심 숫자가 0에서 목표값까지 올라가는 카운트업.
- 화면 진입 시 1회 발동.
- **고정 수치(콘텐츠 팩트는 8번 참조):** 법인 고객 **4,000곳**, 누적 행사 **8,000건**, 재계약률 **92%**. 임의로 바꾸지 말 것.

### 6.3 고객사 로고 마퀴
- 로고가 가로로 무한 흐르는 마퀴.
- 속도는 느긋하게(읽을 수 있게), 끊김 없이 이어지도록 트랙 복제.
- 호버 시 일시정지 정도는 OK.

### 6.4 폰목업 터치 시퀀스
- 스마트폰 목업 안에서 화면이 터치되며 단계가 진행되는 시퀀스.
- 탭 위치에 리플/하이라이트, 화면 전환은 부드럽게.
- "신청이 이렇게 간단하다"는 흐름을 보여주는 용도.

### 6.5 라이브 배차 보드 (시그니처)
- 3번의 호차 배차 격자가 실시간으로 채워지는 모션.
- 셀이 순차적으로 점등/이동하며 "가동 중"인 느낌.
- **이 섹션은 홈페이지의 얼굴이다. 단순 정적 표로 바꾸지 말 것.**

### 6.6 음식 한 샷 비주얼
- 음식 클로즈업 한 컷을 크게 보여주는 비주얼 섹션.
- 스크롤에 따른 가벼운 패럴럭스/스케일 인 정도. 식욕 자극이 목적이니 색·디테일을 죽이지 않는다.

---

## 7. 새 섹션/모션을 추가할 때

1. 먼저 `:root` 토큰과 기존 6개 섹션의 코드 패턴을 읽는다.
2. 같은 이징·같은 IntersectionObserver 패턴·같은 컬러 토큰을 재사용한다.
3. 시그니처(배차 격자)·슬로건·고정 수치는 건드리지 않는다.
4. 모바일에서 먼저 확인한다.

## 8. 콘텐츠 팩트 (변경 금지)

- 슬로건: "젊음이 만든 열정, 깨끗한 푸드트럭의 기준."
- 법인 고객 4,000곳 · 누적 행사 8,000건 · 재계약률 92%.
- 이 수치들은 확정 팩트다. 추측으로 바꾸거나 새 통계를 지어내지 말 것. 수치 변경이 필요하면 사용자에게 확인.

## 9. 작업 워크플로우 (반드시 지킬 것)

- **항상 완성된 전체 `index.html` 파일로 제공한다.** "이 부분만 바꿔서 붙여넣으세요" 식의 부분 패치 지시는 하지 않는다(사용자는 비개발자, 전체 파일 교체 방식을 선호).
- **모든 페이지/섹션이 완성되기 전에는 GitHub 업로드를 제안하지 않는다.**
- 배포 흐름: 완성 파일 제공 → 사용자가 GitHub(`foodtruck-home`)에 업로드 → Vercel 자동배포. 이 흐름을 임의로 바꾸지 않는다.
- 한국어로 간결하게, 실행 중심으로 소통한다.

---

## 10. 하지 말 것 (Don'ts)

- 어두운 네이비 일색 무드로 되돌리기 ❌
- 배차 격자를 평범한 표/리스트로 대체하기 ❌
- CSS/JS를 별도 파일로 분리하기 ❌
- 고정 수치·슬로건을 임의로 변경하기 ❌
- 부분 패치 지시(전체 파일 미제공) ❌
- 완성 전 GitHub 업로드 제안 ❌
- 김추진 채널 아이디어를 홈페이지에 섞기 ❌ (두 주제는 철저히 분리)
