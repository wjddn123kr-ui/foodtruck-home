# 푸드트럭하우스 배포 규칙

배포 흐름: 파일 작성/수정 → git commit·push → Vercel 자동 배포. 하지만 **타이밍에 강한 규칙**이 있다.

## 1. 일괄 배포 — 중간 배포 제안 금지

- 홈페이지는 **모든 페이지가 완성된 뒤 한 번에** GitHub에 올린다.
- 작업 도중 "지금 push 할까요?" / "중간 배포해서 확인해볼까요?" 같은 **부분 배포 제안을 하지 않는다.**
- 작업자가 **명시적으로** "올려줘 / push 해줘 / 배포해줘"라고 할 때만 push 한다. 그 전엔 로컬에서만 작업.
- 로컬 확인은 `미리보기.bat`(→ http://localhost:8123). `include.js`가 fetch 방식이라 `file://` 더블클릭으론 헤더·푸터가 안 뜨므로 반드시 http로 확인.

## 2. 도메인은 맨 마지막

- 도메인 전환은 로드맵 6단계, **맨 마지막**. 그 전까진 기존 사이트(foodtruckhouse.com, Rhymix)를 건드리지 않고 **Vercel 임시 주소**에서만 작업한다.
- 도메인 전환 직전에 이미지·영상을 새 저장소로 이전한다(현재 후기·메뉴 사진은 기존 서버 URL 참조 중).

## 3. push 할 때 규칙

작업자가 배포를 지시한 경우:

- GitHub에 올라간 버전이 **유일한 정본**이다(집·회사 두 곳 작업 → 항상 최신 pull 후 작업).
- 커밋 메시지는 한국어로, **무엇을·왜** 바꿨는지 구체적으로(기존 커밋 스타일 유지).
- 기본 브랜치(main)에 직접 커밋해도 되지만, 큰 변경은 확인받는다.
- push 후 Vercel 자동 배포 → 임시 주소에서 결과 확인 안내.

## 셀프 체크

1. 지금 작업자가 **명시적으로** 배포를 지시했는가? 아니면 push 하지 않는다.
2. 부분/중간 배포를 먼저 제안하려는 건 아닌가?(금지)
3. 배포한다면: 모든 대상 페이지가 완성됐는가? 커밋 메시지가 구체적인가?
4. 도메인 전환 단계가 아니라면 기존 사이트는 그대로 두는가?
